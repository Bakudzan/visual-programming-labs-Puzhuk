## 1. Краткое описание выполненного

В ходе лабораторной работы на no-code платформе **Bubble** было разработано публичное веб-приложение **«ТВП: Пужук Александр — Учёт расходов»**:
1. С помощью встроенного AI-агента Bubble сгенерирован базовый каркас приложения по структуре `header + body + footer` с интерактивными элементами учёта расходов (CRUD), фильтрацией по категориям/датам и сводной статистикой.
2. Изучены руководства **Bubble Build Guides** по проектированию базы данных транзакций и настройке фильтрации списков (`Repeating Group`).
3. Выполнена ручная доработка пользовательского интерфейса (UI) во вкладке `Design`: обновлён заголовок в шапке сайта, создана и применена глобальная цветовая переменная (`red-color`), настроен пользовательский стиль кнопки (`Button-style`) и интегрирован готовый блок из библиотеки компонентов (`Drag & drop UI components`).
4. Спроектирована новая сущность базы данных **«Подписка»** с полями различных типов (`text`, `number`, `date`, `yes/no`) и заполнена начальными записями через `App Data`.
5. На отдельной странице `subscriptions` реализован полный цикл **CRUD (Create, Read, Update, Delete)** для сущности «Подписка», где каждое действие вынесено в отдельный workflow, а также настроена навигация между страницами в шапке приложения.
6. Для выполнения **Ачивки 2 (Plugins)** установлен и настроен плагин **Bootstrap Star Rating**, позволяющий оценивать важность/полезность подписок и расходов по шкале звёзд.

## 6. Освоенные элементы и Workflows

### Элементы интерфейса (UI Elements):
* **Контейнеры:** `Group` (с Flexbox-разметкой `Row` и `Column`), `Repeating Group` (для отображения списков расходов и подписок из БД).
* **Формы ввода (Input Forms):** `Input` (текстовый и числовой ввод), `Date/Time Picker` (выбор даты), `Dropdown` (выпадающий список фильтрации), `Checkbox` (переключатель статуса `Активна`).
* **Визуальные элементы:** `Text`, `Button`, готовые секции из библиотеки `Components`.
* **Плагин-элементы:** `Star Rating` (`Bootstrap Star Rating`) — интерактивная шкала оценки звёздами.
* **Стилизация:** Глобальные переменные цвета (`Styles -> Variables -> red-color`) и пользовательские стили элементов (`Styles -> Button-style`).

### Логика и потоки данных (Workflows):
* **Create (`Create save`):** Событие клика по кнопке «Добавить» -> действие `Data (Things) -> Create a new thing` (тип `Подписка`, заполнение полей из `Input's value`) -> действие `Reset relevant inputs` (очистка формы).
* **Read (`Обновить список подписок` / Data Source):** Чтение записей через `Do a search for Подписка` в `Repeating Group` и принудительное обновление списка (`Display list`).
* **Update (`Edit open edit`, `Edit save`, `Edit cancel`):** Передача выбранной записи в состояние редактирования и сохранение изменений в БД через действие `Data (Things) -> Make changes to thing` (`Current cell's Подписка`).
* **Delete (`Удалить подписку`):** Событие клика по кнопке «Удалить» внутри ячейки `Repeating Group` -> действие `Data (Things) -> Delete thing` (`To delete: Current cell's Подписка`).
* **Navigation:** Переход между страницами `index` и `subscriptions` через действие `Navigation -> Go to page`.

## 8. Выводы

В ходе выполнения лабораторной работы была освоена no-code платформа **Bubble**. Использование встроенного AI-агента позволяет за считанные минуты сгенерировать рабочий прототип приложения со сложной версткой (`header + body + footer`) и базовой структурой данных, однако для точной настройки дизайна и бизнес-логики необходима ручная работа в редакторе. Я научился управлять глобальными переменными цвета и стилями элементов, проектировать реляционные таблицы в разделе `Data`, связывать интерфейс с базой данных через `Repeating Group` и настраивать отдельные цепочки событий (`Workflows`) для всех операций CRUD, а также расширять функциональность приложения с помощью сторонних плагинов.
